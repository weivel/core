The core is weivel's plugin engine, written in C: the one place every decision of the plugin platform is made, so every language sees the same decisions. It decides whether a plugin's manifest is compatible with the host, the order a set of plugins activates in and which requirement is missing or cyclic, which service or capability a plugin may reach and which provider answers it, when a want settles, degrades or is refused (a constrained want asks the caller about the provider's capacity and settles on its polls), what is revoked when a plugin is released, quarantined or forgotten, and what the ledger records about every plugin. It does nothing but decide: it never calls out, owns no clock, opens no file, reads no environment and parses no format, and it holds no plugin object, service implementation or listener, each being an integer handle the caller maps to its own object. Every change lands in one queue the caller drains after each call, and time reaches it only as a number the caller hands in. Its whole interface is one header, `include/weivel/core.h`, a struct ABI with no function pointer in it; the implementation under `src/` builds as a static and a shared library, and `test/` holds its tests and two programs a language's tests use. A language implementation wraps the core and is held to the contract in this tree, one file per module; the conformance kit holds the core to the core tier of its vectors and runs its drift checks against this repository, the core gate among them (the kit's `docs/checks.md` states each), which proves the built core reads nothing of the world and that its interface hands it nothing it could call. How to build the core and run its tests is answered in [the source mirror's root doc](source/README.md); the core is a library, so there is nothing of its own to run.
