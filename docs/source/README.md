The repo root of the core: one CMake project in C11 with no compiler extensions and no dependency beyond the C library and, off Windows, the platform's threads. It builds the same sources three ways. `weivel_core` is the static library, position-independent so a shared library can link it in, and is what the conformance kit links. `weivel_core_shared` is the shared library a foreign function interface loads, its file named `weivel_core` and exporting only what the header marks `WEIVEL_API`; its import library goes to the build's `shared` directory, because on Windows it would otherwise carry the static library's name in the same place. `weivel_core_testing` adds the allocation seam of `src/memory.c` and is built only for the tests that need it, so no library a host links carries the seam. Every target is built with warnings as errors (`/W4 /WX /utf-8` on MSVC, `-Wall -Wextra -Wpedantic -Werror` elsewhere), and programs and shared libraries land in the build's `bin` directory. The tests are added only when the core is the top-level project, so a project that adds the core as a subdirectory, as the conformance kit does, builds the libraries alone. Build and test with `cmake -S . -B build`, `cmake --build build --config Debug` and `ctest --test-dir build --output-on-failure -C Debug`; CI runs that on Linux, Windows and macOS, and once more on Linux under the address and undefined behaviour sanitizers.
